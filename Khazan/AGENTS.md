# Khazan 작업 문서 규칙

1. 모든 작업은 먼저 `0_DOCUMENT_ROUTER.md` 하나만 읽고 요청 도메인을 판정한다.
2. Art 작업은 `Docs/Art`의 필요한 문서만 읽고 갱신한다.
3. Engineering 작업은 `Docs/Engineering`의 필요한 문서만 읽고 갱신한다.
4. 요청이 두 도메인에 걸칠 때만 양쪽의 최소 문서 집합을 읽고, 결과도 각 도메인 문서에 분리 기록한다.
5. 루트의 `1_PROJECT_STATE.md`부터 `7_RUNTIME_CRASH_DIAGNOSTICS.md`까지는 마이그레이션 전 레거시 기록이다. 라우터가 특정 정보를 찾기 위해 지목한 경우가 아니면 선행해서 읽거나 갱신하지 않는다.
6. 문서는 기존 기록을 덮어쓰거나 삭제하지 않고 날짜별 섹션을 하단에 추가한다.
7. 작업이 중단되거나 완료하지 못할 가능성이 있으면 해당 도메인의 `*_WORK_CONTINUITY.md`에 현재 상태, 마지막 검증, 실패 원인, 남은 작업, 정확한 재개 절차를 기록한다.
8. 전수조사는 기존 도메인 지식 문서와 저장된 metadata/report로 답할 수 없을 때만 수행한다. 불가피한 전수조사 결과는 해당 도메인 지식 문서에 재사용 가능한 형태로 남긴다.

## 2026-09-08 수치의 원작 메타데이터 출처 필수

- 사용자 최신 지시: 앞으로 게임 동작/에셋 재현과 관련한 수치는 원작 메타데이터를 근거로 설명하고 구현한다. 이동 속도뿐 아니라 가감속, 회전 속도/각도 임계값, 입력 임계값, 재생률, 블렌드/제동/전이 시간, 거리, 비율 등에도 적용한다. 임의의 “예시값/권장값/일단 테스트할 기본값”을 새로 넣지 않는다.
- 수치를 제시할 때 원작 package/asset 또는 추출 파일 경로, 정확한 property/field/curve/key, 원시 값, 단위와 적용 조건을 함께 기록한다. 관련 원본/버전을 식별하고, 상속/override/배율이 있으면 어떤 조건의 값인지 확인한다. 비슷한 이름의 다른 에셋이나 엔진 기본값을 원작 근거로 대체하지 않는다.
- 원작 메타데이터로부터 계산한 값은 직접 기록된 원본값과 구분한다. 입력 필드와 값, 계산식, 단위·좌표·시간축 변환, 가정과 검증 범위를 공개한다. 추정/실측/임포트 결과를 원작 메타데이터의 직접 확인으로 표현하지 않는다.
- 근거를 찾지 못하거나 metadata만으로 결정할 수 없으면 “미확인/원본 근거 없음”으로 남긴다. 편의상 수치를 채우지 않으며, 그 값의 확정이 필요한 절차는 필요한 자료와 함께 안내한다. 독립적인 구조 설명은 수치 없는 기호/변수로 계속할 수 있다. 원작 값 대신 새 튜닝값을 쓰는 것은 사용자가 별도로 명시적으로 요청/승인한 경우에만 가능하며 출처를 사용자 결정으로 표시한다.
- 코드 예제에도 미검증 gameplay literal을 넣지 않는다. 수학적 상수, 상태 초기화, 엔진 API의 필수 표현과 원작에서 정해야 할 튜닝값은 구분하며, 엔진의 기술적 근거를 원작 수치 출처처럼 설명하지 않는다.
- 이전에 제안한 수치는 기존 코드/문서에 있다는 이유로 원작 검증값이 되지 않는다. 적용 관측과 원작 일치 검증을 분리한다. 기존 기록은 보존하고 미검증 상태를 추가하며, 이 지시만으로 현재 코드/에셋을 일괄 교체하거나 재임포트하지 않는다.
- 후속 수치 작업은 해당 도메인 정본과 저장된 metadata/report에서 시작해 필요한 원본만 표적 확인한다. 이 원칙은 과거 가이드의 임시 숫자 제안보다 우선한다.

## 2026-09-08 공동 구현 설명 방식 고정

- 사용자가 “같이 구현하자”, “구현해보자”와 함께 자세한 설명을 요청하면, 기존 로코모션 공동 작업처럼 사용자가 직접 구현하고 어시스턴트가 이해를 돕는 방식으로 진행한다. 이 표현만으로 게임 C++/BP/에셋을 직접 편집하지 않는다. 직접 수정 요청은 별도로 구분한다.
- 먼저 목표 동작, 이번에 실제 따라 할 범위, 미구현/미확인 범위를 명확히 한다. 현재 정본과 실제 심볼을 확인하고, 과거 제안명을 현재 구현처럼 사용하지 않는다.
- 파일별 생성/수정 위치와 해당 클래스·모듈에 책임을 두는 이유를 코드보다 먼저 설명한다. 입력 의도, gameplay/CMC 제어, snapshot, AnimInstance 파생 데이터, ABP 포즈 재생의 역할을 구분한다.
- 각 변수의 타입, 단위, 초기값 의도, 작성자와 소비자, 갱신/고정/Reset 시점을 설명한다. 각 함수의 용도, 인자/반환값, const/참조 의미, 호출 위치·순서·스레드를 설명한다.
- 제시한 소스는 의미 있는 각 줄과 분기·연산을 빠짐없이 해설한다. 계산식은 좌표계/부호/단위와 손으로 확인할 수 있는 사례를 함께 설명한다. 기하학적 예시와 gameplay 튜닝값을 혼동하지 않는다.
- 에디터 작업은 대상 에셋 경로, 메뉴/상속 변수/노드/핀/연결/전이 조건을 필요한 범위에서 구체적으로 설명하고, 왜 그 작업이 필요한지도 설명한다. 아직 근거가 없는 설정은 임의 숫자로 채우지 않는다.
- 빌드·런타임 확인 절차와 예상 결과, 실패 시 확인할 항목을 함께 제시한다. 어시스턴트가 실제 검사한 범위와 사용자가 적용 후 검사할 범위를 분리하며, 제안 코드를 적용/빌드/PIE 완료로 기록하지 않는다.
- 한 번에 설명되지 않은 큰 코드 덩어리를 넘기지 않고, 의존관계에 맞춰 단계별로 진행한다. 수치의 원작 메타데이터 출처 필수 규칙은 이 설명 방식에서도 그대로 적용한다.

## 2026-09-08 수치 정책 개정 — 원작 우선, 명시된 임시 튜닝값 허용

- 사용자 최신 지시: 최대한 원작 메타데이터를 우선하되, 필요한 경우 어시스턴트가 임의 수치를 선정하고 그 사실을 명시해 사용할 수 있다. 이 절은 앞선 “수치의 원작 메타데이터 출처 필수” 및 공동 구현 설명 절의 일률적 임시값 금지/원본 확보 전 보류 조건을 대체한다.
- 수치를 원작 직접 확인값 / 원작 기반 계산값 / 임시 튜닝값으로 구분한다. 원본값에는 파일·field·원시 값·단위·조건을, 계산값에는 원본 입력·수식·가정을, 임시값에는 원작 근거 미확인 여부·선정 이유·단위·영향·검증 및 조정 기준을 설명한다. 어시스턴트가 고른 숫자를 사용자가 직접 지정한 값이나 원작 검증값으로 표현하지 않는다.
- 기존 정본과 저장 metadata/report를 우선 확인하고 필요한 원본만 표적 조사한다. 근거를 확보하지 못한 필수 값은 임시 튜닝값임을 설명하고 진행할 수 있으며, 같은 목적의 임시값 사용을 매번 다시 승인받거나 원본 자료가 없다는 이유만으로 구현 설명을 보류하지 않는다.
- 임시값은 코드 주석과 설명에서 출처 상태를 드러내고, 소유 클래스의 조정 가능한 설정 또는 적절한 DataAsset 등에 모아 관리한다. 여러 함수에 magic number로 흩어 넣지 않으며, 나중에 원작 근거가 확보되면 의미·단위·조건이 일치하는지 검증한 뒤 교체한다.
- 수치 사용 허용은 기존 코드/에셋 일괄 수정·재임포트 권한이 아니다. 사용자가 직접 따라 구현하는 설명 방식, 기존 변경 보존, 적용 여부와 실제 검증 범위 구분은 유지한다.

## 2026-09-08 캐릭터 아키텍처 v1 확립 — 후속 작업의 필수 기준

- 사용자 요청으로 `Docs/Engineering/CHARACTER_GAMEPLAY_ARCHITECTURE.md`를 앞으로 구현할 전체 구조의 정본으로 확립했다. 기존 검토의 설계 후보와 구분하며, 구현 완료를 의미하지 않는다.
- 캐릭터/이동/액션/AI 기능 설계·리팩터링은 Router → 새 아키텍처 정본 → 해당 현행 구현 문서/소스 순으로 진행한다. 이 순서는 앞선 로코모션 첫 도메인 문서 규칙을 해당 요청에서 대체한다. 현재 변수·검증의 정본은 계속 `Docs/Animation/LOCOMOTION_CURRENT_IMPLEMENTATION.md`다.

- AttackState와 AttackAbility에 같은 액션 수명을 중복 구현하지 않는다. 여러 원인의 제한을 단일 bool의 true 복구로 풀지 않으며, 원인별 handle·실행 ID·취소/실패 cleanup을 설계한다.
- Main AnimInstance에 전투 가능 여부·콤보·피해·스킬 timer를 추가하지 않는다. 실제 소비 없는 helper/관측 멤버/빈 State를 선행 생성하지 않는다. enum·bool·태그·State 클래스는 각각의 의미와 수명에 맞게 사용한다.
- 새 변수/함수/클래스 제안은 정본 14절의 작성자·소비자·갱신/Reset·스레드·취소·Player/AI 공유·수치 출처·검증 항목에 답해야 한다. 기존 설계를 변경해야 하면 ARCH ID와 이유/이관 범위를 날짜별로 먼저 기록한다.
- 다음 공동 구현은 A1의 작은 소단계부터 진행한다. Player/일반 적의 공통 이동·제어 기반과 최소 전투 수직 검증을 거친다. 예전 SprintPivot의 AnimInstance 변수 추가 절차로 돌아가지 않는다.
- 공동 구현의 한 줄씩 설명, 원작 우선/명시적 임시 수치 허용, 사용자 변경 보존, 직접 수정 요청과 설명 요청 구분은 유지한다. 이번 설계 정본 작성은 게임 파일 수정의 포괄적 허가가 아니다.

## 2026-09-08 캐릭터 아키텍처 v2 확정 — Tag–Ability 7계층 개발 의무

- 사용자 최신 지시로 [CHARACTER_GAMEPLAY_ARCHITECTURE.md의 v2 확정 절](Docs/Engineering/CHARACTER_GAMEPLAY_ARCHITECTURE.md#character-architecture-v2)을 이후 설계/개발/리팩터링/검증의 필수 기준으로 채택한다. 앞선 v1의 필수 제어 HFSM·A0–A7 및 검토 단계의 “HFSM 미확정”은 충돌 범위에서 대체한다.
- 공유 gameplay 상태는 캐릭터별 ASC의 태그/GameplayEffect, 액션 실행 수명은 Ability/Task가 소유한다. 별도 CharacterStateMachine 및 Alive/Operational/Incapacitated/Scripted/Dead State 클래스를 이번 마이그레이션에서 생성하지 않는다. 같은 상태를 Character/AnimInstance/FSM의 변경 가능한 bool/enum으로 이중 관리하지 않는다.
- 7계층은 State Matrix / Execution / Math & Consequence / Presentation·AI / GameplayCue / Spatial·Targeting / Interaction이다. 공통 이동은 LocomotionComponent→CMC가 제약/회전/구동을 중재하고, 확정된 피해 결과의 반응은 CombatResponse 책임으로 둔다. 7개 만능 Manager로 구현하지 않는다.
- bool/enum은 내부 관측·유효성·배타 선택에 사용한다. 태그 사전/Ability Asset Tags/Owned Tags/이벤트/Cue를 구분하고, cancel 방향·신규 활성화 차단·실행 중 취소를 명시한다. 태그 문자열/임의 DataAsset만으로 엔진이 모든 규칙을 자동 실행한다고 설명하지 않는다.
- 원인별 Effect/제약/부여 handle, Pawn·요청·실행 ID, 정상/취소/실패/사망/EndPlay cleanup을 설계한다. Notify End만 기다리거나 여러 원인의 태그를 일괄 제거하지 않는다.
- Main AnimInstance는 공통 관측/합성, Locomotion Linked Layer는 이동 포즈·Stop 발 이력이다. worker에서 ASC/Actor를 직접 읽거나 쓰지 않는다. Cue는 순수 피드백, 타깃/워핑/적중은 서로 다른 계약, 상호작용 대상은 결과/보상의 소유자다.
- 후속 순서는 Router → 아키텍처 v2 → [CHARACTER_TAG_ABILITY_MIGRATION.md](Docs/Engineering/CHARACTER_TAG_ABILITY_MIGRATION.md)의 현재 M단계 → 현행 정본/소스다. 첫 단계는 [CHARACTER_TAG_ABILITY_STEP_1.md](Docs/Engineering/CHARACTER_TAG_ABILITY_STEP_1.md)의 M1 공통 ASC 연결이다.
- M1은 엔진 UAbilitySystemComponent와 IAbilitySystemInterface/ActorInfo 수명만 연결한다. 공통 요청 소비가 생기는 M3에서 Khazan ASC/Ability base를 구현한다. 빈 subclass/State/helper/미사용 태그·DataAsset을 먼저 생성하지 않는다.
- v2의 ARCH-01–19 및 기존 14절의 작성자·소비자·수명·스레드·취소·Player/AI·수치 출처·검증 항목을 따른다. 계약 변경은 관련 ARCH ID와 근거/이관 범위를 먼저 날짜별로 기록한다.
- 문서 확립은 게임 파일 직접 수정의 포괄적 허가가 아니다. 공동 구현은 파일 위치/책임, 변수·함수·각 줄, 에디터/빌드/런타임 절차를 설명하고 사용자가 적용하는 방식이다. 적용/빌드/PIE는 실제 결과가 있을 때만 완료로 기록한다.
- InGame 한정, 모든 Start 제외, Walk/Run 발별 Stop·Sprint 단일 Stop, Walk 좌/우 Turn·Run Turn 제외·별도 SprintPivot, 현재 root-locked Stop/CMC 이동, 원작 우선·명시된 임시값 허용과 기존 사용자 변경 보존을 유지한다.
